## Goal

keel can read a terms file for a worst-of autocall, reject anything malformed with a line-numbered error, and say exactly which payoff terms are verified. Nothing is ever filled in silently.

## The file format

Every term is a value plus where it came from:

```yaml
level: { value: 0.95, status: advisor, source: advisor-screenshot }
```

- `status` is one of, from most to least trusted: `primary` (pricing supplement or final terms), `document` (confirmation or statement, authoritative only for what that document states), `advisor` (screenshot or email), `user` (typed, no source), `estimate` (generated by a rule; carries `rule`), `assumed` (an explicit default; carries `note`), `unknown` (`value: null`).
- A term in conflict has this form instead, with at least two candidates kept in file order:

```yaml
maturity:
  status: conflict
  candidates:
    - { value: 2030-06-14, source: confirm-a }
    - { value: 2030-06-17, source: screenshot-b }
```

- `sources` is a map from source id to `{ kind, file }`, where `file` is a relative path inside the user's data folder. Absolute paths are an error.
- The first line is `schema: mln-terms/0.1`.

Top-level sections: `schema`, `id`, `category` (`mln`), `structure` (`autocall-snowball-worst-of`), `identifiers`, `issuer`, `dates` (`trade`, `settlement`, `maturity`, `first_call_observation`, optional `observation_schedule` as a list of terms), `underlyings` (`basket: worst_of`, `members` with `ticker` and `initial`), `call` (`level`, `non_call_months`, `frequency`), `premium` (`rate_per_year`, `accrual`), `barrier` (`level`, `observation`, `below_barrier`), `economics` (`issue_price`, `estimated_value`, `fees`), `sources`.

## Scope

1. **Schema.** `schemas/mln-terms/0.1.json`, JSON Schema draft 2020-12, describing the format above. Unknown keys are errors.
2. **Loader.** `loadTerms(text: string, fileName: string): Result<Terms, TermsError[]>` in `packages/core/src/terms/`. Pure: it takes text, never reads files. YAML 1.2 core schema only; duplicate keys, anchors and aliases are errors; dates stay ISO strings and are validated as dates. Every error carries line, column, a JSON path, and a message a person can act on.
3. **Verification summary.** `verificationSummary(terms)` returns `{ verified, total, unverifiedCritical }` over payoff terms. Payoff terms are everything under `call`, `premium` and `barrier`, each `underlyings.members[].initial`, `dates.maturity`, and `dates.observation_schedule`. Only `primary` counts as verified. Critical terms are each initial level, the observation schedule, maturity, `call.level`, `barrier.observation` and `barrier.below_barrier`.
4. **Date flags.** `dateFlags(isoDate)` returns `['weekend']` for a Saturday or Sunday, computed from the ISO date alone (no clock, no time zone). The loader attaches flags to every date it reads; it never rejects a weekend date.
5. **CUSIP check.** A failed check digit is a warning on the result, not an error.
6. **Fixtures.** `fixtures/synthetic/terms/valid/`: a fictional "Example Bank SA" note on tickers ALFA, BRVO, CHRL and DLTA with a mix of every status, one conflict, and one weekend date. Fixture CUSIPs pass the check digit, start with `ZZZ`, and are listed exactly in `tools/tripwire/allowlist.txt` with the reason "synthetic fixture". `fixtures/synthetic/terms/invalid/`: one file per error class (missing schema line, duplicate key, alias, unknown status, wrong value type, conflict with one candidate, absolute source path, unknown top-level key).

## Honesty tests (`terms.honesty.test.ts`)

- A `document` or `advisor` status never counts as verified, for any payoff term.
- A conflict never counts as verified and keeps every candidate in order.
- The loader never invents a value: every leaf in the result exists in the input, and absent optional fields stay absent.
- `unknown` stays `null` all the way through.

## Non-goals

The payoff engine; schedule generation and the holiday calendar; PDF import; any UI; writing or editing terms files; resolving conflicts (a later slice, and only with a document).

## Mutation floor

At least three killed mutants per claim, listed in the PR body. Required among them: counting `document` as verified; dropping the second conflict candidate; accepting an alias; treating Friday as a weekend; filling a missing `estimated_value` with 0.

## Dependencies

Candidates: a YAML 1.2 parser that reports positions and duplicate keys, and a JSON Schema 2020-12 validator. The builder may instead hand-write validation against the schema. Every dependency added needs a justification and license line in the PR body.
