## Goal

The S00 gate stays trustworthy as later slices lean on it. Tests that spawn nested runs stop timing out under load. Honesty-file discovery is proved from Vitest's own structured report. A vendor's commit address can appear in a review record without tripping the tripwire. `@keel/core` declares the test runner it uses.

## Scope

1. **Nested-run timeouts.** A test file under `tools/**/test/` starts subprocesses only through the spawning helpers exported from `tools/acceptance/test/helpers.mjs` or by calling a tool function that spawns (such as `runProbes`, the verify runner or the namespace-probe runner); no test file other than `helpers.mjs` imports `node:child_process`. Spawning is tracked per exported symbol, through any chain of imports. A symbol is a spawning entry point if it is an exported helper in `helpers.mjs` that starts a subprocess (such as `run()`), or an export of a module that imports `node:child_process`, or an export of a module that imports or re-exports any spawning entry point. A module that imports only non-spawning symbols (such as `write()` from `helpers.mjs`) does not become spawning, and its exports are not entry points. The self-test computes this set from the import graph of `tools/` itself; it is never a hand-kept list. Every test that calls one, in any tooling test file, declares an explicit per-test timeout taken from one exported constant, `NESTED_RUN_TIMEOUT_MS`, at least 60 000. In-process tests keep Vitest's default. No global timeout change.
2. **Process-isolated temp files.** Every file a tooling test writes inside the repo (today the temporary `*.honesty.test.ts` files under `packages/core/src` and the network test's `zz-guard.test.mjs`; any later one too) is named per process, with the process ID and a random part, created only for that test, and removed in `finally`. Files that need not live in the repo go to a fresh temp directory instead. Two copies of the suite running at once in one checkout never share a file name.
3. **Structured honesty discovery** (ideas 5 and 7). The honesty-discovery test runs `pnpm --filter @keel/core test <name> --reporter=json --outputFile=<temp file>` and asserts from that JSON, not from printed text: the temporary file's path appears in `testResults`; the passing run reports 1 passed and 0 failed; the failing run reports 1 failed and exits nonzero. No assertion reads pnpm's echo of its own command. `pnpm -s test:tooling -- test-contract` then passes, as `pnpm verify` does.
4. **Vendor bot addresses** (idea 9). A new file, `tools/tripwire/vendors.txt`, lists exact commit addresses of the agent vendors that write to this repo, one per line as `address<TAB>reason`. The tripwire validates it before scanning: a malformed line is a hit. A listed address is exempt from the email class only, matched exactly and case-insensitively, in every tracked file and commit message; inside `vendors.txt`, only addresses on valid lines are exempt. It ships with one entry: the address Cursor commits under in this repo, which is the `user.email` its build prompts set and which S00's build commits carry (`git fetch origin refs/pull/3/head && git log -1 --format=%ae 8b9dfee`). Reason: "Cursor agent commit address". `noreply` addresses stay exempt as today. Adding a vendor later is a sensitive-path change Beni merges. The allowlist keeps its `fixtures/` scope.
5. **`@keel/core` declares Vitest** (idea 6). `packages/core/package.json` gains `vitest` as a devDependency at the same version as the root. It still has no runtime dependency.

## Non-goals

SHA-pinning the workflow's actions (idea 1); passing runner variables into the CI namespace (idea 4); widening the allowlist beyond `fixtures/` (idea 3, declined); any change to another tripwire class; any product code.

## Mutation floor

At least three killed mutants per claim, listed in the PR body with the test that kills each. Required among them: dropping the timeout from one helper-spawned test; computing the spawning set without following wrappers or re-exports; exempting a wrapper or re-export of a spawning helper from `helpers.mjs`; marking a write-only wrapper as spawning; importing `node:child_process` in a test file; using a fixed temp-file name in one test; setting the constant below 60 000; dropping the honesty glob; exempting a vendor address from every class; matching vendor addresses by substring instead of exactly; skipping `vendors.txt` validation; giving `@keel/core` a runtime dependency.

Review checks how the honesty-discovery test proves its claim (Scope 3: from Vitest's JSON report, never from printed text), and the floor lists no mutant for it. A runtime guard is possible: extract the probe, inject its runner and report reader, and require it to fail on broken reports paired with correct printed text. This slice does not add that guard, because it covers the extracted probe only; a top-level test rewired to printed assertions would still pass, so review would still have to read the wiring.
