## Goal

The S00 gate stays trustworthy as later slices lean on it. Tests that spawn nested runs stop timing out under load. Honesty-file discovery is proved from Vitest's own structured report. A vendor's commit address can appear in a review record without tripping the tripwire. `@keel/core` declares the test runner it uses.

## Scope

1. **Nested-run timeouts.** Every tooling test that spawns a nested `pnpm`, Vitest, `tsc` or `node` run (today in `test-contract`, `determinism` and `network`) declares an explicit per-test timeout, taken from one exported constant in `tools/acceptance/test/helpers.mjs` (`NESTED_RUN_TIMEOUT_MS`, at least 60 000). In-process tests keep Vitest's default. No global timeout change.
2. **Concurrent-safe temp files.** The honesty-discovery test writes its temporary `*.honesty.test.ts` files with a per-run unique suffix (process ID plus random), so concurrent runs of the suite never share a file name, and removes them in `finally`.
3. **Structured honesty discovery** (ideas 5 and 7). The honesty-discovery test runs `pnpm --filter @keel/core test <name> --reporter=json --outputFile=<temp file>` and asserts from that JSON, not from printed text: the temporary file's path appears in `testResults`; the passing run reports 1 passed and 0 failed; the failing run reports 1 failed and exits nonzero. No assertion reads pnpm's echo of its own command. `pnpm -s test:tooling -- test-contract` then passes, as `pnpm verify` does.
4. **Vendor bot addresses** (idea 9). A new file, `tools/tripwire/vendors.txt`, lists exact commit addresses of the agent vendors that write to this repo, one per line as `address<TAB>reason`. The tripwire validates it before scanning: a malformed line is a hit. A listed address is exempt from the email class only, matched exactly and case-insensitively, in every tracked file and commit message; inside `vendors.txt`, only addresses on valid lines are exempt. It ships with one entry: the address Cursor commits under in this repo, which is the `user.email` its build prompts set and which S00's build commits carry (`git fetch origin refs/pull/3/head && git log -1 --format=%ae 8b9dfee`). Reason: "Cursor agent commit address". `noreply` addresses stay exempt as today. Adding a vendor later is a sensitive-path change Beni merges. The allowlist keeps its `fixtures/` scope.
5. **`@keel/core` declares Vitest** (idea 6). `packages/core/package.json` gains `vitest` as a devDependency at the same version as the root. It still has no runtime dependency.

## Non-goals

SHA-pinning the workflow's actions (idea 1); passing runner variables into the CI namespace (idea 4); widening the allowlist beyond `fixtures/` (idea 3, declined); any change to another tripwire class; any product code.

## Acceptance criteria

| # | Criterion | Reproducing command and what it asserts |
| --- | --- | --- |
| AC1 | Every nested-run test carries the named timeout | `pnpm test:tooling -- test-contract`: a self-test reads the tooling test sources and asserts that every test calling `run(...)` on `pnpm`, `node`, Vitest or `tsc` passes `NESTED_RUN_TIMEOUT_MS`, and that the constant is at least 60 000 |
| AC2 | The suite survives concurrent load on a cold install | Recorded in the PR body, not part of `verify`: on Node 24, from a fresh clone, `pnpm install --frozen-lockfile` then three concurrent `pnpm test:tooling` runs, repeated three times, with zero timeouts and zero failures; the exact shell loop and its output are in the PR body |
| AC3 | Honesty discovery is proved from Vitest's JSON report | `pnpm -s test:tooling -- test-contract` and `pnpm verify` both pass; the test fails when the core include glob drops `*.honesty.test.ts`, and fails when the failing temporary test is made to pass |
| AC4 | Concurrent runs do not collide | `pnpm test:tooling -- test-contract`: two temporary-file names generated in one process differ, and no `zz-acceptance*` file remains under `packages/core/src` after the suite (`git status --porcelain --untracked-files=all -- packages/core` prints nothing) |
| AC5 | Vendor addresses are exempt from the email class only | `pnpm test:tooling -- tripwire`: a listed address in a tracked file and in a commit message is not a hit; a near-miss of it (one character changed, or a different domain) is a hit; a listed address does not exempt any other class on its line; a malformed `vendors.txt` line is a hit; an unlisted address added inside `vendors.txt` is a hit |
| AC6 | The repo scans clean with the shipped list | `pnpm verify:tripwire` exits 0 |
| AC7 | `@keel/core` declares Vitest and has no runtime dependency | `pnpm test:tooling -- test-contract`: `core.devDependencies.vitest` equals the root's, and `core.dependencies` is absent or empty |
| AC8 | The gate stays green | `pnpm install --frozen-lockfile && pnpm verify` on Node 24 and Node 26, and the `verify` check on the PR |

## Mutation floor

At least three killed mutants per claim, listed in the PR body with the test that kills each. Required among them: dropping the timeout from one nested-run test; setting the constant below 60 000; asserting honesty discovery from printed text again; dropping the honesty glob; exempting a vendor address from every class; matching vendor addresses by substring instead of exactly; skipping `vendors.txt` validation; giving `@keel/core` a runtime dependency.

## Dependencies

None new. `vitest` moves into `packages/core`'s devDependencies at the existing version; the lockfile changes accordingly.

## Build rules carried from S00

Every commit is green in CI before the next is pushed (PR #3, ruling 4). Tripwire positives are generated at test time and never committed; no realistic value in any test source.
