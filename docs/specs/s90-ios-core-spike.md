## Is story 9.1 enough as the phone's only data path?

The test comes first because every row below depends on it. The assumption is that the desktop app is the source of truth, and that its export reaches the phone through the Files app, with no network and no sync service.

**As transport, yes.** Story 9.1 produces plain YAML and CSV files. The phone picks them through the Files app and needs no account, server or network. AirDrop to Files and a USB copy through Finder keep the files between the owner's own devices. iCloud Drive also appears in Files, but a file put there leaves the owner's machines, so the phone's copy names that difference. Story 9.1 is not built yet, so the spike uses a synthetic stand-in generated by seed.

**As content, no.** Story 9.1's acceptance names terms, observations and alerts. The Section 8 floor for the phone, "a read-only responsive view of Today and the instrument summary", needs more:

### Alerts: what can be scheduled ahead

iOS gives the app no timed background run it can rely on (`BGTaskScheduler` runs at the system's discretion), and on the phone a close arrives only by import. So a rule can reach a closed app only when its fire time is known at import. Severity keeps Section 4's meaning: High and Critical become a notification, Notice goes in a weekly digest notification, and Info stays in the app.

| Alert | In M1 as | Scheduled ahead? | On the phone |
| --- | --- | --- | --- |
| A1 Barrier proximity | Must | No | After import only |
| A2 Likely call | Could | No | After import only |
| A3 Observation approaching and result | Must | Reminders yes, result no | T-5 in the digest, T-1 as a notification, result after import |
| A4 Call detected | Must | No | After import. "Observation passed, no close imported" can be scheduled |
| A5 Maturity approaching | Should | Yes | T-180, T-30, T-5 |
| A6 Rating or outlook change | Should | Age only | Rating-age timer, if ratings travel |
| A7 Large single-name move | Could | No | After import only |
| A8 Stale data | Must | Yes, as a timer | Last close plus 3 trading days, and one per observation date; each import resets them |
| A9 Terms still unverified | Must | Yes | T-30, T-7, weekly digest line |
| A10 Source conflict | Must | No | Raised at import |
| A11 Corporate action | Could | No | After import only |
| A12 Review ritual | Not in the M1 list | Yes | Quarterly digest line |

Two limits that follow, for the ADR:

- A scheduled notification fires whatever has happened since. A note called on the desktop keeps its T-1 reminders on the phone until the next import cancels them. So each body carries the export's as-of date.
- The pending limit: Apple forum answers report a limit of 64 per app, keeping the soonest ([thread](https://developer.apple.com/forums/thread/811171)). A monthly five-year note has 55 observations, so the app schedules a rolling window and refills it on each open and import. Q5 verifies this on a device.

### Q1 Bundle

Can `@keel/core`, including `ajv` 8.20.0 and `yaml` 2.9.1, build into one script with no Node built-ins and load into a JSContext from a Swift test target that runs on macOS?

```bash
pnpm --dir spike/ios-core --ignore-workspace install --frozen-lockfile && node spike/ios-core/build.mjs && node spike/ios-core/check-bundle.mjs
```

```bash
swift test --package-path spike/ios-core --filter BundleLoadTests
```

`check-bundle.mjs` exits nonzero on `require(`, a `node:` specifier, a reference to `process`, or the string `montecarlo`, and prints the bundle's bytes. `BundleLoadTests` fails on any JSContext exception and asserts that `dateFlags`, `loadTerms` and `verificationSummary` are functions.

Known traps, none yet run:

- `yaml`'s `exports` map gives Node its `process`-using build and everything else the browser build, so the bundle must not take the `node` condition.
- `ajv`'s `getLogger` returns the global `console` when no logger is given (`ajv/dist/core.js:545`), and `schema-map.ts` gives none, so `new Ajv` runs at module load with whatever the host provides.
- `yaml`'s browser `warn` calls `console.warn`. If a host has no `console`, that throws inside `toJS`, and the catch in `load.ts` would report it as `alias`.

Whether a JSContext defines `console` decides these. Any shim the host needs is a finding, listed in the results.

### Q2 Parity

For every file in `fixtures/synthetic/terms/`, valid and invalid, does the JSContext output match Node's byte for byte, including each diagnostic's line, column and order? There are 31 files, 2 valid and 29 invalid (`git ls-files fixtures/synthetic/terms | grep -c '\.yaml$'`).

```bash
sh spike/ios-core/run-parity.sh
```

```bash
sh spike/ios-core/run-parity.sh --inject-diff
```

The first exits 0 only if every comparison is byte-identical, and prints fixtures, locales, engines and variants. The second alters one byte of one output and must exit 1, or the harness cannot fail.

- **Node side:** runs `packages/core/src/index.ts` directly, unbundled, so that a bundling difference counts as a difference.
- **Output:** one line per file, `JSON.stringify({ file, result, summary })`, where `summary` is `verificationSummary(result.terms)` when `result.ok`.
- **Comparison:** `cmp`, in both engines, under `en_US` and `haw_US`, and for each bundle variant in Q3.
- **Locale check:** each run records `new Intl.Collator().resolvedOptions().locale`. If the two runs in one engine report the same locale, that engine's run fails: a test under one locale twice is not a test under two. If a JSContext's default locale cannot be set from a test target, that is a finding.

`load.ts` no longer sorts with `localeCompare`: Beni's ruling replaced it inside PR #13, at `c527df8`, after `dedupe` gave a different order under `LC_ALL=haw_US.UTF-8`. At `3bceb20`, `git grep -n localeCompare -- packages` prints only a test stub, and neither library's loaded code calls a locale API (`grep -rlE 'localeCompare|toLocale|Intl\.' node_modules/.pnpm/yaml@2.9.1/node_modules/yaml/browser/dist node_modules/.pnpm/ajv@8.20.0/node_modules/ajv/dist | wc -l` prints `0`). The two-locale test stays: it is the check that nothing else depends on locale.

**Reported, not gating:** the same comparison on inputs edited in memory, because earlier reviews found them to be edge cases. A complex key, an alias as a key, a leading BOM, CRLF line endings, a character outside the Basic Multilingual Plane before a fault (columns count UTF-16 units here), `0000-02-29`, flow nesting to 2000 and block nesting to 1000. A divergence is reported in the results and put to Beni.

### Q3 Code generation and load time

`schema-map.ts` calls `ajv.compile` at load, and `ajv/dist/compile/index.js:89` is `new Function`. Does that work inside a JSContext? How long does it take without a JIT on a real iPhone? Does an `ajv` standalone precompiled validator remove the question?

Two bundle variants, each through Q2:

- **`compile`:** the merged core, unchanged.
- **`standalone`:** the spike's build swaps `schema-map.ts`'s compile for a generated validator through a build-time plugin. Core is not edited. If this is the variant that passes, the core change is filed through the normal workflow and is never made on the spike branch.

```bash
swift test --package-path spike/ios-core --filter LoadTimeTests
```

```bash
xcodebuild test -project spike/ios-core/App/KeelSpike.xcodeproj -scheme KeelSpike -configuration Release -destination "platform=iOS,id=$KEEL_SPIKE_UDID" DEVELOPMENT_TEAM="$KEEL_SPIKE_TEAM" -allowProvisioningUpdates -only-testing:KeelSpikeTests/LoadTimeTests
```

**Measured, per variant, in a Release build with no debugger attached where Xcode allows it:** create a JSContext and evaluate the bundle, which includes `ajv.compile` for the `compile` variant, 20 fresh times, and report the median and worst. Then `loadTerms` on `example-autocall.yaml`, 20 times, median and worst. The test also reports whether the device's run differs from a macOS JSContext, because "no JIT in-app" is a premise here that the spike tests rather than states.

**Beni runs the device line.** Only his iPhone can. The results quote his log, and Pass 1, Pass 2 and Pass 2.5 mark those numbers as Beni's run rather than as re-run.

## Decision rule

Registered here before any spike code exists. The spike branch is cut from a `main` that holds this file with Beni's thresholds in it.

**Choose Path A if all of these hold** for one bundle variant:

1. **Q2:** parity is 100% on every fixture, in both engines and both locales, against the merged core with nothing edited.
2. **Q3:** both medians on the device are under the thresholds below.
3. **Q5:** no App Review blocker to executing bundled JavaScript.

**Choose Path B only if A fails one of those.** A close call is reported as a close call, and is not resolved by preference.

Pre-registered edge cases:

- If only `standalone` passes, the result is Path A, conditional on that core change landing through the normal workflow. Beni rules.
- A host shim such as `console` does not fail Q2. A change needed in core does: at that SHA Q2 fails, and the results say what would fix it, so Beni can weigh it as a close call.
- A harness that cannot fail, or a skipped comparison, is not a pass. Q1 failing means Q2 cannot pass.
- The path-neutral items under Q5 do not count for either path.
- Q4's size informs Beni's reading of a close call. It does not override a clear result either way.
- Beni rules on the results, and ADR-0009 moves from Proposed then.

**Thresholds, proposed for Beni to set before spike code starts:**

| Measure, on Beni's iPhone, Release build | Proposed threshold | Close call if within |

| Median to create a JSContext and evaluate the bundle, 20 fresh runs | 500 ms | 400 to 600 ms |

## Anchor

The script behind the ESTIMATE under "Decision rule". Run it from a clone with `pnpm install --frozen-lockfile` done, as `node anchor.mjs "$PWD"`, and as `node --no-opt --no-maglev --no-sparkplug anchor.mjs "$PWD"`. `--jitless` cannot be used, because Node's TypeScript stripping needs WebAssembly.

```js
import { readFileSync, readdirSync } from "node:fs";
import { join } from "node:path";
const root = process.argv[2];
const t0 = performance.now();
const core = await import(join(root, "packages/core/src/index.ts"));
const t1 = performance.now();
const dir = join(root, "fixtures/synthetic/terms/valid");
const big = readFileSync(join(dir, "example-autocall.yaml"), "utf8");
const s = [];
for (let i = 0; i < 20; i += 1) {
  const a = performance.now();
  core.loadTerms(big, "b.yaml");
  s.push(performance.now() - a);
}
s.sort((a, b) => a - b);
console.log(JSON.stringify({ importMs: t1 - t0, medianMs: s[10], worstMs: s[19] }));
```
